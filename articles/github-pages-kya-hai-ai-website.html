GitHub Pages क्या है? AI से बनी वेबसाइट मुफ़्त में कैसे डालें

TECH RAWAT AI टीम28 अक्टूबर 20265 मिनट में पढ़ें

मुख्य बातें

  • GitHub Pages स्थिर फ़ाइलों को वेबसाइट बनाता है; PHP, Ruby या Python जैसी सर्वर-साइड भाषाएँ नहीं चलतीं
  • मुफ़्त वाले GitHub खाते में Pages सार्वजनिक रिपॉज़िटरी के लिए है, इसलिए निजी जानकारी, पासवर्ड या API कुंजी फ़ाइल में न रखें
  • AI से एक ही HTML फ़ाइल बनवाकर index.html नाम से रिपॉज़िटरी में डालें और Pages चालू करें
  • सीमाएँ: साइट 1 GB तक, महीने का ट्रैफ़िक 100 GB की नरम सीमा, एक घंटे में 10 बिल्ड की नरम सीमा

GitHub Pages क्या है? यह GitHub की मुफ़्त सेवा है जो आपके रिपॉज़िटरी की स्थिर फ़ाइलों, यानी HTML, CSS और JavaScript, को वेबसाइट की तरह चलाती है। AI से बनी एक पेज की वेबसाइट को index.html नाम से रिपॉज़िटरी में डालें, Pages चालू करें और बने पते पर खोलकर जाँचें।

AI से HTML की वेबसाइट बनवाना आसान है, पर उसे इंटरनेट पर सबको दिखने लायक बनाने में लोग अटक जाते हैं। यहाँ पूरा रास्ता है: AI से फ़ाइल बनवाना, GitHub पर रखना, Pages चालू करना और प्रकाशित करने से पहले की जाँच। कई लोग इसे रोमन में "Github Pages Kya Hai" लिखकर भी खोजते हैं।

GitHub Pages क्या करता है और क्या नहीं

GitHub के अपने दस्तावेज़ों के अनुसार Pages आपके रिपॉज़िटरी में रखी स्थिर फ़ाइलों को वेबसाइट की तरह प्रकाशित करता है। वही दस्तावेज़ साफ़ कहते हैं कि यह PHP, Ruby या Python जैसी सर्वर-साइड भाषाओं को नहीं चलाता। इसलिए लॉगिन, डेटाबेस या फ़ॉर्म जमा होकर कहीं सेव होने वाली साइट इसकी मदद से नहीं चलेगी; सूचना, पोर्टफ़ोलियो, कैलकुलेटर या लैंडिंग पेज जैसी साइटें चलेंगी।

GitHub के पन्ने के अनुसार मुफ़्त वाले GitHub खाते में Pages सार्वजनिक रिपॉज़िटरी के लिए मिलता है। सार्वजनिक का मतलब है कि रिपॉज़िटरी की हर फ़ाइल कोई भी देख सकता है, इसलिए वहाँ निजी चीज़ें रखना ठीक नहीं।

पहले AI से फ़ाइल बनवाएँ

AI को ऐसी साइट बनाने को कहें जो एक ही फ़ाइल में पूरी हो, ताकि प्रकाशन का काम सीधा रहे:

मेरी [दुकान या विषय] के लिए एक पेज की हिंदी वेबसाइट बनाओ। सब कुछ एक ही HTML फ़ाइल में हो, CSS उसी फ़ाइल के अंदर हो, कोई बाहरी स्क्रिप्ट, पासवर्ड या API कुंजी न हो। फ़ोन पर ठीक दिखे। सबसे ऊपर शीर्षक, बीच में 3 हिस्से और नीचे संपर्क का हिस्सा रखो।

जो फ़ाइल मिले उसे पहले अपने कंप्यूटर पर ब्राउज़र में खोलकर देख लें। AI से बने कोड की जाँच का तरीका AI कोड की 5 क़दम में जाँच वाले लेख में है, और वही आदत यहाँ भी काम आती है।

GitHub पर प्रकाशित करने के 5 क़दम

  1. GitHub पर खाता बनाएँ और एक सार्वजनिक रिपॉज़िटरी बनाएँ। अपने नाम से सीधा पता (नामवाली साइट) चाहिए तो रिपॉज़िटरी का नाम आपके उपयोगकर्ता नाम के बाद .github.io होना चाहिए; GitHub के दस्तावेज़ यही बताते हैं।
  2. रिपॉज़िटरी में फ़ाइल जोड़ें और उसे index.html नाम दें, फिर AI की दी HTML उसमें चिपकाकर सेव करें।
  3. रिपॉज़िटरी की सेटिंग्स में Pages खोलें और प्रकाशन वाले हिस्से में शाखा से प्रकाशित करने का विकल्प चुनें।
  4. GitHub के दस्तावेज़ के अनुसार स्रोत शाखा कोई भी हो सकती है और फ़ोल्डर रिपॉज़िटरी का मूल (/) या Docs चुना जा सकता है। शुरुआत में मुख्य शाखा और मूल फ़ोल्डर चुनें, फिर सेव करें।
  5. कुछ मिनट रुककर वही Pages पन्ना खोलें और Visit Site दबाएँ। एक घंटे में बदलाव न दिखे तो GitHub के दस्तावेज़ Jekyll बिल्ड त्रुटियाँ देखने को कहते हैं।

पता खुल जाए तो उसे फ़ोन पर भी खोलकर देखें। बाद में फ़ाइल बदलनी हो तो रिपॉज़िटरी में वही फ़ाइल सुधारें; शाखा में बदलाव सेव होते ही साइट अपने आप फिर प्रकाशित होती है।

प्रकाशित करने से पहले AI की फ़ाइल में क्या देखें

रिपॉज़िटरी सार्वजनिक है, इसलिए फ़ाइल में अपना फ़ोन नंबर, घर का पता, पासवर्ड या किसी सेवा की API कुंजी न हो। AI कभी-कभी नमूने के तौर पर ऐसी जगहें बना देता है जहाँ कुंजी भरनी होती है; उसे असली कुंजी से न भरें। क्या नहीं डालना चाहिए, इसकी सूची AI को कभी न बताएँ ये 6 चीज़ें में है। फ़ाइल में बाहर के किसी अनजान पते से स्क्रिप्ट लोड होती दिखे तो उसे हटा दें या AI से बिना बाहरी स्क्रिप्ट के दोबारा बनवाएँ।

सीमाएँ: कितना बड़ा और कितना ट्रैफ़िक चलेगा

नीचे की सीमाएँ GitHub के दस्तावेज़ों में लिखी हैं और 28 अक्टूबर 2026 को देखी गईं। ये बदल सकती हैं, इसलिए बड़े प्रोजेक्ट से पहले GitHub का Pages सीमाओं वाला पन्ना देख लें।

क्या फ़ॉर्म या ऑटोमेशन चल सकता है

स्थिर साइट पर फ़ॉर्म भरवाकर डेटा सेव करना या ईमेल भेजना ख़ुद Pages नहीं करता, क्योंकि उसके लिए सर्वर चाहिए। ऐसे काम के लिए अलग सेवा जोड़नी पड़ती है; बिना कोड के ऑटोमेशन की शुरुआत n8n से पहला ऑटोमेशन वाले लेख में समझाई है। अपना डोमेन जोड़ना GitHub के दस्तावेज़ों में बताया गया है, पर वह दूसरा क़दम है।
